## What shipped

- `src/lib/registries/nppes.ts` — client for the public CMS NPPES v2.1 API
  mirroring the discovery-provider precedent: injectable fetch, `configured`
  false and no call unless `TALENTOS_REGISTRY_NPPES=1` (`mock` for tests),
  URL builders, `mapNppesResults` with explicit field picks only (number,
  first/last name, credential, taxonomies, practice LOCATION city / state /
  office telephone), `Errors[]` and HTTP errors surfaced, watermarked mock
  records.
- `src/lib/registries/index.ts` — status, the registry's own search page as
  link-out, and the label copy: "registry-matched · CMS NPPES" with the
  explainer that it is identity and taxonomy, not reachability or current
  licensure.
- `src/lib/core/payloads.ts` — `nppesRecordSchema`, the only shape that can
  be persisted.
- `src/lib/db/schema.ts` — `candidate_registry_matches` (unique per
  candidate + registry, cascade on candidate delete, `matched_by`
  `local-owner`).
- `src/lib/services/registries.ts` — `prefillFromCandidate` (name split,
  state from geography, NPI from a Wave D link-out),
  `searchNppesForCandidate` (in memory, API order, identity-matcher
  strength, no score), `confirmRegistryMatch` (upsert + official link-out
  source), `clearRegistryMatch`, `getRegistryMatch`, `listRegistryMatches`.
- `src/lib/actions/registries.ts`, `src/components/registry-match.tsx`
  (off / search / matched states), candidate page card above Sources.
- `deleteCandidate` and `exportCandidate` include registry matches.
- `.env.example`, `playwright.config.ts` (`TALENTOS_REGISTRY_NPPES: "mock"`).
- Docs: `DATA_MODEL.md`, `docs/BACKLOG.md` (Registries follow-ups),
  `docs/DECISIONS.md` D-032.
- The artifact-side `npiAdapter` stays `wired:false` (D-021).
